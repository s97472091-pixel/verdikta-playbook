📊 Scoring Criteria Breakdown

Every Verdikta submission is evaluated by a dual-model AI jury (typically GPT-5.2 + Claude Sonnet 4.5, each weighted 50%). Each model scores independently against the rubric, then scores are averaged. Here's how the common criteria work:

CriterionTypical WeightWhat Evaluators CheckScore Impact
no_fabrication MUST PASS Every claim must be verifiable. Inline raw data, reproducible commands, real URLs. No hallucinated stats. Fail = 0
data_accuracy 0.25 – 0.35 Numbers match source data. No rounding errors. Stats are internally consistent. Cross-reference with on-chain data. ±15 pts
analysis_depth 0.25 – 0.30 Goes beyond surface. Identifies patterns, draws conclusions, provides context. Not just listing data. ±10 pts
clarity 0.15 – 0.20 Well-structured with headers, tables, clear language. Easy to scan. No dense paragraphs. ±8 pts
actionable_insights 0.10 – 0.15 Practical recommendations. Not vague advice — specific, evidence-based suggestions. ±5 pts
💡 Key insight: The no_fabrication gate is binary — if you fail it, your score is 0 regardless of everything else. Always include inline raw data and reproducible verification commands.

How Dual-Model Scoring Works

Both models evaluate your submission independently against the same rubric. The final score is a weighted average. This means:

  • You need to pass both models — one high score won't save a low one
  • GPT tends to be stricter on no_fabrication (flags unverifiable claims)
  • Claude tends to be stricter on clarity (flags poor structure)
  • Target threshold + 5% margin to account for variance

🚨 Common Failure Patterns

Real examples of what causes submissions to fail. Each pattern includes the bounty ID and the fix.

💥 ORACLE_TIMEOUT — Binary/Image Content

#114 Submission included image files or binary attachments. Oracle cannot process non-text content and times out, resulting in automatic score of 0.

Fix:

Never attach images, PDFs, or binary files. Convert everything to text: use code blocks for data, ASCII art for diagrams, markdown tables for charts.

💥 ORACLE_TIMEOUT — Meta Sections with Error Language

#114 Social bounty files contained meta sections (checklist, proof notes, "how this was verified"). The oracle reads ALL text as content, and words like "error", "checklist", "proof" trigger confusion.

Fix:

Strip ALL meta content. No checklists, no proof notes, no "submitted by" sections. Your file should contain ONLY the deliverable content — nothing about the submission process itself.

💥 no_fabrication — Unverifiable Claims

#129 (5 attempts, max 78.5%) Added claims like "no KYC", "24/7 support", "instant transactions", "minutes" — none of which were in the bounty description. GPT flagged each as unverifiable.

Fix:

For localized bounties, stick STRICTLY to the bounty description. Don't embellish. Every sentence must be traceable to the source material. Adding details NOT in the description LOWERS your accuracy score.

💥 no_fabrication — Data Not Inline

#64 (6 attempts, best 37.5%) Raw data was in separate .json files or referenced via curl commands without inline copy. Oracle can't access external files — it only sees what's in the submission text.

Fix:

Embed ALL raw data in fenced code blocks inside your submission markdown. Include a Python verification script that computes your claimed numbers from the inline data. This is the strongest defense against no_fabrication.

💥 Data Inconsistency

#64 Claimed "87 bounties had only 1 hunter" in the executive summary, but the detailed section showed "10 zero-sub + 77 single-hunter = 87". The headline was technically correct but misleading — evaluator flagged the inconsistency.

Fix:

Every number in your submission must be internally consistent. Run your own verification: grep for every number and cross-check against your raw data. One inconsistency can tank your data_accuracy score.

💥 Live URL Not Accessible

Social media posts get deleted or made private. Reddit posts get removed by mods. Twitter threads get taken down. If the oracle can't verify your URL at evaluation time, you score 0.

Fix:

Use permanent URLs: GitHub Pages, GitHub repos, archived content. For social posts, include a screenshot AND the live URL. For Medium, ensure the article is public (not draft).

💥 Wrong Method Names / Placeholder URLs

LLM-generated code often has invented method names (e.g., list_bounties() instead of list_jobs()) or placeholder URLs like REPLACE_WITH_PUBLIC_GITHUB_URL.

Fix:

Always verify method names against actual API docs. Run sed to find and replace all placeholder URLs before pushing. Test every example script actually works.
